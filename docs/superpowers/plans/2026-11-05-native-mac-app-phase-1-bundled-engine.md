# Native Mac app, phase 1: the bundled engine: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `Tecopa Plateworks.app` (`org.plateworks.tecopa`), which carries its own Python and engine, starts the engine on port 8848 and opens the web studio. Then prove its poster is byte-equal to the venv's, and prove it runs with the repo moved away.

**Architecture:** The Python engine changes very little: five path fixes and one debug field. A Foundation-only layer in TecopaKit owns the bundle layout, the engine environment, plate seeding and the engine process. A thin AppKit app target, generated by XcodeGen, calls it. Shell scripts, with their logic in tested Python helpers, assemble, check and sign the bundle, seed the DEM cache, archive DEMs to Dropbox and run the proofs.

**Tech Stack:** Python 3.14.2 (python-build-standalone in the bundle, python.org in the reference venv), FastAPI and uvicorn, pytest. Swift 6 with XCTest, SwiftPM (`tools/tecopa`), XcodeGen 2.44, Xcode 27.2. Bash, `codesign`, `uv` 0.9.

**Spec:** `docs/superpowers/specs/2026-11-05-native-mac-app-phase-1-bundled-engine-design.md` (approved by Dom, 2026-11-05). Its section numbers are cited as "spec 5.3" and so on. Read it before any task.

## Global Constraints

- Bundle id `org.plateworks.tecopa`; display name and `CFBundleName` "Tecopa Plateworks" in full; executable `TecopaPlateworks`; macOS 14 minimum; not sandboxed; no entitlements file; hardened runtime OFF in phase 1.
- Engine port 8848; reference port 8849 (proofs only). Log `~/Library/Logs/TecopaPlateworks.log`. Data root `~/Library/Application Support/Tecopa Plateworks/`. The runs folder stays `…/Application Support/TecopaPlateworks/runs` (`Runtime.runsFolder`); do not rename it in phase 1.
- Interpreter: `https://github.com/astral-sh/python-build-standalone/releases/download/20260127/cpython-3.14.2%2B20260127-aarch64-apple-darwin-install_only.tar.gz`, SHA-256 `e8891a012ad178d7afc0db4dcad611d6156e6402947578fc91acbbdf1930eebd`. Taken from the release's SHA256SUMS; the first build confirms it against the downloaded bytes.
- Two interpreter copies, never mixed (invariant 13): `Contents/Resources/python-engine/` and `…/python-prep/`. No `PYTHONPATH`, no `.pth`.
- Engine command, exactly: `<bundle>/Contents/Resources/python-engine/bin/python3.14 -P -m uvicorn app.main:app --app-dir <bundle>/Contents/Resources/engine --host 127.0.0.1 --port 8848`, cwd = data root.
- Never put a font in the repo, the bundle or a DMG (invariant 10). Never re-stamp `sources.json` (invariant 12). Swift holds no render logic, coordinate math or spec rules.
- Every commit is on `claude/project-thread-iekg24`. The fast suite (`.venv/bin/python -m pytest -n auto -m "not slow" -q`) and `swift test --package-path tools/tecopa` are green before each commit that touches them. GitHub Actions stays off.
- **Gated, each waits for Dom's typed yes:** the Developer ID signing spike, installing into `/Applications` (it replaces the launcher), the zlib fallback, and the real Dropbox archive run (PWI-73: Dropbox space). No task here does any of them unasked.
- Settled here where the spec was silent (Dom can overrule each):
  - `settings.json` is a flat JSON object keyed by env name. Only `TECOPA_ORDERS_DIR`, `TECOPA_INTAKE_DIR` and keys starting `TECOPA_FONT` pass.
  - The engine environment also drops `PYTHONSTARTUP` and `__PYVENV_LAUNCHER__`, as `ScriptRunner.droppedVariables` does.
  - Every quit of an owned engine reads the jobs and confirms, as spec 5.5 says; the Dock's Quit, logout and `osascript` all count. One exception: `tecopa engine stop --force` first writes `<AS>/.quit-forced`. A marker younger than 15 s skips the confirm, and the app deletes it. Without `--force`, the tool already refuses while jobs run, so no dialog appears.
  - `TECOPA_APP` overrides the app path for the tool and doctor, so `dist/` can be driven before the install yes. The tool opens the app **by that path** (`open -g <path>`), never by bundle id: LaunchServices may hold several copies with one id.
- "Dirty tree" means tracked changes only: `git diff --quiet HEAD && git diff --cached --quiet`. Untracked files are allowed. A script that refuses a dirty tree is committed before its first real run.
  - "An engine on port 8848 is not answering." is the not-answering copy. One job reads "1 job is running. Quitting ends it."

## Review Focus

1. **The old launcher's engine is already on 8848 when the app starts.** The app adopts it silently and serves a venv engine. Expected: the app adopts, logs the adopted engine's version, and logs a mismatch line when it differs from `TecopaEngineVersion`. Test in Task 18.
2. **First launch with no Application Support folder.** Expected: the data root, `regions/`, `blobs/` and `uploads/` are created before spawn, and seeding fills `regions/`. Test in Task 14.
3. **A malformed `settings.json`.** Expected: no spawn. An alert names the file and says it is not valid JSON. Tests in Task 12 (throws) and Task 17 (copy).
4. **Paths with spaces everywhere** ("Tecopa Plateworks.app", "Application Support", "Tecopa Orders"). Expected: nothing splits on a space. Every layout, environment, seeder and seed-script test uses a path with a space.
5. **Quit while the engine is still starting.** Expected: no confirm, because jobs cannot be read from an engine that is not up yet. The spawned child is stopped. `EngineHost.spawn` hands the app the pid before the readiness wait. Tests in Task 14 (`testAChildStillStartingCanBeStopped`) and Task 17 (`afterJobs(.unknown)` gives `.stopEngine`).
